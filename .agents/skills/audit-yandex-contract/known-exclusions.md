# Known exclusions

These deviations were reviewed and accepted as intentional. Apply them as described in [Known exclusions](./SKILL.md#known-exclusions).

| Exclusion | Rationale | Re-evaluate if |
| --- | --- | --- |
| **Web script loading (including Invisible CAPTCHA):** The web adapter loads `captcha.js` without `render=onload&onload=...` and calls `window.smartCaptcha.render` after the script's `load` event. This accepts the loader deviation for every `render` parameter, including `invisible: true`, and the package's claim to support invisible mode on web. | This avoids a global `onload` function and allows reuse of an already loaded script. The container lacks the `smart-captcha` class, so it is not rendered automatically. Yandex's statement that Invisible CAPTCHA is only connected using the advanced method is already accounted for by this exclusion. The alternative's equivalence remains undocumented; this is an accepted deviation, not proof of contract compliance. | Official documentation explicitly states that `window.smartCaptcha` or `render` is unavailable, or a `render` parameter (including `invisible`) is ignored, without `render=onload&onload=...`. Requiring the advanced method, showing its URL, or claiming invisible-mode support on web does not by itself meet this condition. |
| **Numeric `WidgetId`:** The web interop declares `render` as returning `JSNumber` and passes that value to widget methods. Yandex documents a unique `WidgetId` but does not specify its JavaScript primitive type. | Browser and end-to-end testing identified the returned ID as numeric and exercised the bridge on JavaScript and WebAssembly. Retaining `JSNumber` reflects observed behavior, not a type guaranteed by Yandex's published contract. | Yandex documents a specific non-numeric type for `WidgetId`. |
| **On-demand token:** `getResponse` is not exposed. | The token is delivered through `onChallengeSolved`. | The package claims to support on-demand token retrieval. |
| **JavaScript error payload:** `onJavaScriptError` does not expose the `javascript-error` payload (`filename`, `message`, `col`, `line`). | The callback is a notification and also reports adapter failures without a SmartCaptcha payload, such as exceptions from `render` or widget methods. | The package claims to expose error details. |
| **Success event:** The `success` event is not passed to `subscribe`. | The package handles success through the documented `render` `callback` parameter; `CaptchaEvent.challengeSolved` notes a reliability concern with the subscribed event. | The `callback` render parameter is deprecated or removed. |
| **Unsubscribe function:** The web interop declares `subscribe` as returning `void` instead of `UnsubscribeFunction`. | The package never unsubscribes individual listeners. According to the documentation, `destroy` removes the widget's listeners. | The package needs per-event unsubscription, or `destroy` no longer removes listeners. |
