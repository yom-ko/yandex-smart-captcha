# Agent context: Source of truth

This directory is the **only** place to edit canonical context for AI agents.

The provider-specific files are generated by [`build-agent-context.sh`](../build-agent-context.sh), which can be run manually or — once the pre-commit hook in [`.githooks/`](../.githooks/) is [enabled](#enabling-the-hook) — automatically on every relevant commit.

## Ownership

The files and directories under **Generated outputs** are "managed targets" that are fully owned by the generator.

| Source            | Generated outputs                                                                                  |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| `project.md`      | `AGENTS.md` `.claude/CLAUDE.md` `.github/copilot-instructions.md`                                  |
| `rules/<name>.md` | `.claude/rules/<name>.md` `.cursor/rules/<name>.mdc` `.github/instructions/<name>.instructions.md` |
| `skills/<name>/`  | `.claude/skills/<name>/` `.cursor/skills/<name>/` `.github/skills/<name>/`                         |

> **Important:** Never manually create or edit files in those output locations, as any manual change is overwritten and any extra file is deleted on the next generator run.

## Generation

Generation is all-or-nothing: all outputs are built in a temporary directory first, and the repository is not modified until the complete build succeeds. Installation uses a two-phase swap — every target is copied next to its destination first, then swapped in with a rename — and is rolled back if a swap fails.

Source requirements:

* The project root must contain the `build-agent-context.sh` generator script.
* Rules must be regular `.md` files, and each skill must be a directory containing `SKILL.md`.
* Rule and skill names may contain only lowercase ASCII letters, digits, `.`, `_` and `-`. They must start with a letter or digit and must not end with `.`.
* Symlinks anywhere under `.agents/` are rejected, so source resolution cannot escape the repository.
* Hidden (dot-prefixed) entries in `rules/` and `skills/` are ignored, and `.DS_Store` files are never copied.
* `.agents/` and the parent directories of generated targets (e.g., `.claude/`) must be real directories, not symlinks.

## Enabling the hook

Set up the custom hooks path once:

```bash
git config core.hooksPath .githooks
```

To keep `.agents/` the single source of truth, the hook implements the following high-level logic:

```text
Read managed targets from the staged generator
└─ fail → abort commit

Staged changes in the generator, .agents/, or managed targets?
├─ no → skip regeneration, continue commit as usual
└─ yes
    ↓
    Unstaged changes in the generator or unstaged/untracked files in .agents/?
    ├─ yes → abort commit
    └─ no
        ↓
        Ignored untracked files in .agents/ other than .DS_Store?
        ├─ yes → abort commit
        └─ no
            ↓
            Regenerate outputs
            ├─ fail → abort commit
            └─ success
                ↓
                Stage managed targets, including deletions
                ↓
                Commit
```

When `.agents/`, the generator script itself, or any generated target is staged, the hook regenerates the outputs and stages all managed targets, including deletions. It refuses to run if the generator or `.agents/` has unstaged changes or untracked files (both ignored and non-ignored) other than `.DS_Store`. The commit is aborted if generation fails, e.g., because of an invalid rule name or a symlink.

> **Note:** Avoid pathspec commits such as `git commit <path>`. The hook may regenerate and stage managed targets, but those files are not included unless they match the commit's pathspec. Use a regular `git commit` so that source changes and generated outputs are committed together.

Hooks can be bypassed with `--no-verify`, so also run `--check` in a CI pipeline as a safety net.

## Updating context directly

To update the agent context without committing anything, run the generator directly:

```bash
./build-agent-context.sh
```

To verify that the generated outputs match `.agents/` without modifying anything (e.g., in a CI pipeline), run:

```bash
./build-agent-context.sh --check
```

## Writing path-dependent rules

> **Important:** Different AI providers use different frontmatter fields for path-scoped rules. When creating or editing `rules/`, specify the same file patterns in `globs`, `paths` and `applyTo` fields so the generated rules remain semantically equivalent across providers.

```yaml
---
description: Rule description
globs: "lib/src/*.dart,test/src/*.dart"
paths:
  - "lib/src/*.dart"
  - "test/src/*.dart"
applyTo: "lib/src/*.dart,test/src/*.dart"
alwaysApply: false
---
```
